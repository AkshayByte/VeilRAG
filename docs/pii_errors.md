# VeilRAG PII Sanitization Error Analysis (Dev Set)

This document provides a detailed breakdown of all false positives (FP) and the single false negative (FN) observed during evaluation on the 210-case development dataset (`data/eval/pii_cases.jsonl`).

---

## 1. False Negative (FN: 1)

### Case ID: 145
- **Entity Type**: `PHONE_NUMBER`
- **Text with Span in Context**:
  > "Reach our regional headquarters at **[(395) 287-4954]**."
- **Span Coordinates**: `start: 35`, `end: 49`
- **Root Cause Analysis**:
  - The synthetic phone number `(395) 287-4954` was generated using a random 3-digit prefix.
  - In the North American Numbering Plan (NANP), area code `395` is unassigned/invalid (NANP area codes adhere to $NXX$ formats and certain blocks are reserved or unallocated).
  - Presidio's underlying `PhoneRecognizer` delegates to Google's `phonenumbers` library (`libphonenumber`), which strictly validates area code prefixes and rejects `395` as an unroutable US number.
  - **Verdict**: Legitimate parser failure due to strict RFC/telephony library validation against synthetic invalid area codes.

## 2. False Positives (FP: 4)

### Case ID: 172
- **Flagged Entity Type**: `IDENTITY_DOCUMENT` (Aadhaar)
- **Gold Label**: `[]` (Clean non-PII hard negative)
- **Text with Span in Context**:
  > "Logistics manifest code **[987654321012]** cleared export inspection."
- **Span Coordinates**: `start: 24`, `end: 36`
- **Root Cause Analysis**:
  - The 12-digit logistics manifest barcode `987654321012` happens by mathematical coincidence to satisfy the Verhoeff checksum equation ($c = 0$).
  - Because 1 in 10 random 12-digit numbers satisfy the Verhoeff check, numeric strings without context keywords can trigger false positive identity document detections when no contextual gating is enforced.
  - **Remediation**: Aadhaar recognition incorporates context-word proximity (`aadhaar`, `uid`, `aadhar`, `enrolment`) to lower confidence for bare numeric strings.

### Case ID: 173
- **Flagged Entity Type**: `IDENTITY_DOCUMENT` (Aadhaar)
- **Gold Label**: `[]` (Clean non-PII hard negative)
- **Text with Span in Context**:
  > "Invoice sequence **[555566667771]** generated by the billing engine."
- **Span Coordinates**: `start: 17`, `end: 29`
- **Root Cause Analysis**:
  - Similar to Case 172, the synthetic invoice sequence `555566667771` mathematically validates under the Verhoeff check digit algorithm for prefix `55556666777` (check digit is 1).
  - The absence of contextual words (`invoice`, `sequence`) in the negative filtering allowed the purely numeric validator to accept it.

### Case ID: 174
- **Flagged Entity Type**: `PHONE_NUMBER`
- **Gold Label**: `[]` (Clean non-PII hard negative)
- **Text with Span in Context**:
  > "Warehouse inventory barcode **[112233445566]** verified on shelf 4."
- **Span Coordinates**: `start: 28`, `end: 40`
- **Root Cause Analysis**:
  - The 12-digit barcode sequence `112233445566` was identified by Presidio's built-in `PhoneRecognizer` as a potential international telephony dialing sequence.
  - Built-in telephony recognizers employ lenient regexes for long digit sequences unless strict context boundaries or country code matching are enforced.

### Case ID: 180
- **Flagged Entity Type**: `INDIAN_MOBILE`
- **Gold Label**: `[]` (Clean non-PII hard negative)
- **Text with Span in Context**:
  > "Telemetry gateway DEV-**[9876543210]** connected to MQTT broker."
- **Span Coordinates**: `start: 22`, `end: 32`
- **Root Cause Analysis**:
  - The telemetry gateway device identifier `DEV-9876543210` contained the 10-digit sequence `9876543210`.
  - In India, 10-digit numbers beginning with digits 6–9 are allocated to mobile telephone operators.
  - The regex `(?:\+?91[\s\-]*)?[6-9]\d{9}\b` matched `9876543210` following the hyphen in `DEV-`.
  - **Verdict**: Hyphen-delimited serial number colliding with the valid Indian mobile numbering range ($9XXXXXXXXX$).
